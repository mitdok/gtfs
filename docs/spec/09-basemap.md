# 09. 自前ベースマップ（MapLibre地図基盤）仕様

[02章 F-10](./02-requirements.md) で「自前MapLibre地図基盤を地図アダプタ経由で利用する」と定めた。本章はその**地図基盤側の要件**を、GTFS編集用途に特化して定義する。地図基盤は別資産として整備が進む（行政境界等の一般的データは整備済み・仮実装あり）前提で、**編集ツールの背景地図として満たすべき水準**と、**追加で揃えるべきデータ**を明らかにする。

## 9.1 目的と性格

- 本サービスにおける地図は**編集の道具**である。観賞用・汎用地図ではなく、「停留所を正しい位置に置く」「経路（shape）を道路に沿って引く」「地名と停留所名を照合する」作業を支えることが唯一の目的。
- したがって評価基準は美しさではなく **(a) 位置照合の手がかりの多さ、(b) オーバーレイ（停留所ピン・経路線）の視認性、(c) オンプレ含む配信のしやすさ** の3点。

## 9.2 機能要件

| ID | 要件 |
|----|------|
| M-1 | MapLibre GL JS で表示できるベクタタイル（MVT）＋ style.json を提供する。 |
| M-2 | 日本語ラベル（地名・駅名・施設名）を描画できる（グリフのセルフホスト）。 |
| M-3 | ズーム z8〜z17 を実用域とする（z17 以上はオーバーズームで対応可）。 |
| M-4 | 静的配信できる形式（PMTiles 推奨）で、オンプレ環境でも Web サーバ1台で配信可能。 |
| M-5 | CORS を許可し、編集ツールとは別オリジンでも動作する。 |
| M-6 | 出典・ライセンス表記（attribution）をスタイル内に持ち、MapLibre の attribution control に表示される。 |
| M-7 | ライト基調のスタイルを必須、ダークは任意。 |
| M-8 | スタイル URL（StyleRef）を編集ツール側に注入するだけで切替できる（地図アダプタとの契約。[04章4.4](./04-screens.md)）。 |

## 9.3 ズーム帯別の表示要件（編集作業との対応）

編集作業は3つの空間スケールで行われる。各スケールで「何が見えなければならないか」を定める。

| ズーム帯 | 編集作業 | 必須レイヤ | あると良い |
|----------|----------|------------|------------|
| **広域 z8–11** | 路線網全体の把握、市町村間路線の確認 | 行政境界（市区町村）、主要道路（高速・国道）、鉄道線・主要駅、海岸線・主要水域、市町村名 | 県境の強調 |
| **中域 z12–14** | 系統・パターンの編集、経路の概形確認 | 全道路（県道・市町村道まで）、鉄道駅すべて、河川、大字・町丁目名、主要施設（病院・学校・庁舎・商業施設） | 土地利用（市街地/緑地の塗り分け） |
| **詳細 z15–17** | 停留所の置局（正確な位置決め）、交差点付近の照合 | 道路の詳細形状（交差点形状が判読できること）、施設名ラベル、（任意）建物外形 | 一方通行等の道路属性、横断歩道・信号位置 |

> **最重要レイヤは道路中心線**。バスは道路上を走り、停留所は道路沿いに置かれるため、道路の形状・種別が判読できない地図はこの用途では機能しない。行政境界はあくまで広域の文脈付けであり、それだけでは編集地図にならない点に注意。

## 9.4 データ整備状況と追加で揃えるべきデータ

「行政境界などの一般的なデータは整備済み」を前提に、本用途で**追加が必要なもの**を優先度付きで挙げる。

| 優先 | データ | 用途 | 入手元候補 |
|------|--------|------|-----------|
| ★★★ | **道路中心線（種別属性付き）** | 編集地図の主役。経路照合・置局 | 国土地理院ベクトルタイル（道路中心線）/ OpenStreetMap |
| ★★★ | **鉄道線形・駅** | 乗換関係の確認、位置の手がかり | 国土数値情報 N02（鉄道）/ 地理院ベクトル |
| ★★★ | **地名・注記（市町村名〜大字・町丁目名）** | 停留所名と地名の照合 | 地理院ベクトル（注記）/ 国土数値情報 |
| ★★☆ | **水域・河川・海岸線** | 地形の手がかり、橋＝バス経路の制約 | 国土数値情報 W05 / 地理院ベクトル |
| ★★☆ | **主要公共施設POI（病院・学校・庁舎・駅前広場等）** | 停留所名の由来照合・置局の基準点 | 国土数値情報（公共施設）/ OSM |
| ★★☆ | **既存バス停留所（全国）** | 他事業者停留所との位置照合・参考表示 | 国土数値情報 P11（バス停留所） |
| ★☆☆ | 建物外形（z15+） | 詳細置局時の手がかり | 基盤地図情報 |
| ★☆☆ | 土地利用・緑地 | 背景の判読性向上 | 国土数値情報 |
| ★★★ | **グリフ（Noto Sans CJK JP 等のSDF化フォント）** | 日本語ラベル描画（M-2）。これが無いとベクタ地図に日本語が出ない | Noto フォントから生成しセルフホスト |
| ★★☆ | スプライト（アイコン: 駅・バス停・病院等） | 記号表示 | 自作（SVG→sprite） |

> 出典・利用条件の整理も「データ整備」に含む。地理院タイル・国土数値情報・OSM はそれぞれ出典表記/ライセンス（OSMはODbL）が異なるため、スタイルの attribution に正しく合成すること（M-6）。

## 9.5 スタイル設計指針

編集オーバーレイ（GTFSデータ）が主役、ベースマップは脇役。

1. **低彩度・グレートーン基調**。道路は白〜薄灰の面/線、水域は淡青、緑地は淡緑まで。
2. **赤系・濃青系をベースマップで使わない**。これらは編集オーバーレイ（停留所ピン=赤系、選択=青系、経路線=高彩度）の専用色として予約する。
3. ラベルは日本語優先・控えめなサイズ。停留所ピンのラベルと競合しないよう、z15+ では施設ラベルの密度を抑える。
4. 既存バス停留所レイヤ（P11）は既定で非表示とし、編集ツール側からレイヤトグルで表示できるようにする（参考情報であり、自データと混同させない）。
5. ライト/（任意）ダークの2テーマは同一ソース・別 style.json で提供する。

## 9.6 配信構成

```
┌──────────────────────┐
│  オブジェクトストレージ / 静的Webサーバ │
│   ├ tiles.pmtiles      （ベクタタイル一式・単一ファイル） │
│   ├ style-light.json   （スタイル） │
│   ├ glyphs/{fontstack}/{range}.pbf │
│   └ sprites/sprite@2x.png/json │
└──────────────┬───────┘
               │ HTTP(S) + Range Requests + CORS
        MapLibre GL JS（編集ツール内・地図アダプタ経由）
```

- **PMTiles を第一候補**とする: 単一ファイル＋Range リクエストで配信でき、タイルサーバ常駐が不要。SaaS（CDN配信）とオンプレ（nginx 等）で同一構成が使える。
- 代替: tileserver-gl / martin 等のタイルサーバ。動的に差し替えたい場合のみ。
- キャッシュ: タイルは immutable 扱い（ファイル名にバージョン付与）、style.json は短TTL。
- 更新: 地図データの更新はタイル一式の再生成・差し替えで行う（年数回程度を想定）。

## 9.7 編集ツールとの接続契約（地図アダプタとの境界）

- 編集ツールは **style.json の URL（StyleRef）だけ**を知る。タイルURL・glyphs・sprites はスタイル内で完結させる（M-8）。
- 設定注入: Web フロントは環境変数（例: `VITE_MAP_STYLE_URL`）でスタイルURLを受け取る。未設定時は**暫定フォールバック**（後述 9.8）で動作する。
- 編集オーバーレイ（停留所・経路線・ハイライト）は**地図アダプタが実行時に追加する動的レイヤ**であり、ベースマップの style.json には含めない。ベースマップ側は前述の予約色を避けること以外、オーバーレイを意識しなくてよい。
- レイヤトグル（既存バス停等）が必要なレイヤは、style.json の `metadata` に `{"gtfs-studio:toggle": "<表示名>"}` を付与する。アダプタはこれを読んで UI にトグルを生やす。

## 9.8 段階導入

| 段階 | ベースマップ | 説明 |
|------|--------------|------|
| 仮実装（現在） | 地理院タイル（ラスタ・淡色）をフォールバックとして使用 | 出典表記の上で利用可。自前基盤が未確定でも編集デモが成立する |
| 自前基盤 v1 | 自前ベクタタイル（PMTiles）＋ライトスタイル | 9.3 の必須レイヤを満たした時点で切替（スタイルURL注入のみ） |
| 自前基盤 v2 | ダークテーマ、既存バス停レイヤ、map matching 用道路ネットワーク連携 | F-5-3（経路の道路追従）への接続 |

## 9.9 性能・品質基準

- タイル1枚の目標サイズ: 中央値 ≤ 100KB、最大 ≤ 500KB（z14 市街地）。
- 初期表示（スタイル＋初期タイル）: ブロードバンドで 2 秒以内。
- 行政境界・水域は低ズームで適切に簡略化（ダグラス=ポイカー等）し、広域表示を軽くする。
- 検収: 豊橋市中心部・郊外（渥美半島方面）・市境界部の3地点で、9.3 の各ズーム帯チェックリストを満たすことを確認する。
