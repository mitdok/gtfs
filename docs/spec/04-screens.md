## 4.2 主要画面の詳細

### S-02 プロジェクトダッシュボード
- 現在の検証ステータス（エラーN件/警告M件）をバッジ表示し、クリックで S-13 へ。
- 公開状況（最新公開版・配信URL・施行待ち版）を表示。
- クイックアクション: 「ダイヤを編集」「検証する」「公開する」「zipをダウンロード」。
- 統計: 停留所数/経路数/便数、データ範囲（calendar の最早〜最遅）。

### S-05 停留所編集（一覧＋地図 連動）
- 左: 表（stop_code, name, name_kana, lat, lon, parent）。仮想スクロールで大量行に対応。
- 右: **自前MapLibre地図基盤**（F-10、地図アダプタ経由）。表で選択した停留所をハイライト、ピンのドラッグで緯度経度更新、地図クリックで新規停留所の座標取得。
- 親子（標柱/停留所）をツリーで表現。近接停留所の重複検知警告。
- インライン編集・一括編集（CSV貼付け）対応。
- 地図はあくまで補助。地図基盤が未提供/オフラインの環境でも、lat/lon の数値編集で停留所編集は完結できる（F-10-5）。

### S-07 パターン編集
- 経路を選び、その配下のパターンを管理（上り/下り、行先）。
- パターンの停留所列を、停留所マスタからドラッグ＆ドロップで構成。順序入替・挿入・削除。
- 各停留所に「先頭からの既定所要時間（default_offset）」「距離」を設定 → ダイヤ展開の基準。
- 既存便がある状態で停留所列を変更した場合の影響（再展開/上書き保持）を確認ダイアログで提示。

### S-08 ダイヤ編集（中核 / 西沢ツールのダイヤ表に相当）
- **レイアウト**: 縦軸＝当該パターンの停留所（上から順）、横軸＝便（列）。各セル＝通過時刻。
- **便の追加**: 「便を追加」→ 先頭停留所の発車時刻を入力すると、pattern_stops の offset から各停留所時刻を自動展開。
- **セル編集**: セルを直接編集すると、その便の当該停留所が override 扱いになる（バッジ表示）。
- **一括操作**: 列のコピー（n分後ろにずらして複製）、間隔指定での連続生成、選択便への運行区分一括割当。
- **24時超**: `25:10` のような入力を許容し、内部は秒で保持。
- **表示切替**: 運行区分（平日/土日）でのフィルタ、便の並べ替え（発時刻順）。
- **整合性表示**: 時刻の逆転・空白・パターン不整合をセル単位でハイライト。
- キーボード中心の高速入力（Tab/Enter移動、貼付け）を重視。

### S-13 検証結果
- エラー/警告/情報の3段階で分類。GTFS-JP必須・参照整合・推奨ルール別にグルーピング。
- 各指摘から該当画面・該当行へワンクリックでジャンプ。
- 「致命的エラーあり＝公開不可」を明示。警告のみなら公開可（要確認チェック）。
- 実行プロファイル、仕様ロック状態、標準バリデータ名・バージョン、実行日時を表示する。
- MVPリリース検収では、[11章](./11-release-acceptance.md) のA-01〜A-10の合否を管理者向けに表示する。

### S-14 公開・版管理
- 「版を作成」: 現在の作業データを検証 → 問題なければスナップショット化し版番号付与。
- 版一覧: 版番号・作成者・コメント・検証結果・公開状態・施行日。
- 版間差分: 停留所/経路/便の追加・変更・削除サマリ。
- 公開操作: 即時公開 or 施行日予約。公開で配信URL（最新版エイリアス）が当該版を指す。
- 配信URL表示: `最新版URL`（固定エイリアス）＋ `版固定URL`。コピー導線とGoogle Maps申請ガイド。
- 外部公開連携: **GTFSデータリポジトリ（gtfs-data.jp）への登録・更新**ボタン（連携設定済の場合）。登録状況・最終送信日時を表示。
- ロールバック: 過去版を最新版エイリアスに再割当。

## 4.3 横断UX方針
- 自動保存（作業データはライブ更新、明示保存は不要）。重要操作のみ確認。
- 変更履歴と undo（少なくともセッション内）。
- 日本語UI優先。専門用語にはツールチップ解説（agency=事業者 等）。
- 大量データ前提でのパフォーマンス（仮想化テーブル、サーバーサイドページング）。

## 4.4 地図アダプタ（Map Adapter）インターフェース

停留所編集(S-05)・描画編集(S-11)は、自前MapLibre地図基盤(F-10)を**地図アダプタ**越しに利用する。これにより、地図基盤の仕様が未確定でも編集UIの実装を進められ、地図基盤の差し替え（仮実装→本番、オンプレ別構成）にもUI側を変更せず追従できる。

### 設計意図
- 編集UIは「停留所のピンを置く/動かす」「線の頂点を編集する」といった**抽象操作**だけを地図アダプタに依頼する。MapLibreのスタイルやタイルURL、レイヤ構成などの内部仕様はアダプタ内に隠蔽する。
- 地図基盤の仕様確定前は、アダプタ実装を**仮実装（暫定スタイル/タイル）**で差し替える。確定後はアダプタ内のみ更新する。

### インターフェース（TypeScript・概念定義）
```ts
// 編集UI ⇔ 地図基盤 の境界。実装はMapLibreを内包する。
interface MapAdapter {
  init(opts: { container: HTMLElement; style: StyleRef; center: LngLat; zoom: number }): Promise<void>;
  destroy(): void;

  // 停留所マーカー
  setMarkers(markers: Array<{ id: string; lngLat: LngLat; label?: string }>): void;
  highlightMarker(id: string | null): void;
  onMarkerDragEnd(cb: (id: string, lngLat: LngLat) => void): void;

  // 線形（shape）
  setLine(id: string, points: LngLat[], opts?: { editable?: boolean }): void;
  onLineEdit(cb: (id: string, points: LngLat[]) => void): void; // 頂点追加/移動/削除

  // 地図操作・取得
  onMapClick(cb: (lngLat: LngLat) => void): void; // 新規停留所の座標取得等
  getBounds(): BBox;                              // 表示領域（範囲内のみロード等に利用）
  flyTo(target: LngLat | BBox, opts?: { padding?: number }): void;

  // 任意・将来: 地図基盤データを使ったmap matching（F-5-3）
  matchRoute?(points: LngLat[]): Promise<LngLat[]>;
}

type LngLat = { lng: number; lat: number };
type BBox = { west: number; south: number; east: number; north: number };
type StyleRef = string | object; // 地図基盤が提供するスタイル参照（URL or スタイルJSON）
```

### 留意
- 座標の**真実は数値データ（DBのlat/lon）**。地図はその可視化・編集手段であり、地図が無くても編集は成立する（F-10-5）。
- アダプタはフロントエンドの一コンポーネント。地図基盤がサービスとして別ホスト/別ポートで動く場合も、`StyleRef`・タイルURLの注入で吸収する。
