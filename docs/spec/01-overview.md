# 01. 概要

## 1.1 背景

地域公共交通（特に路線バス・コミュニティバス）のオープンデータ化において、デファクト標準であるGTFS、および日本の拡張仕様であるGTFS-JP（国土交通省「標準的なバス情報フォーマット」）が広く用いられている。しかし事業者が自力でGTFSを整備するハードルは高く、これを緩和するために西沢明氏により開発・公開された通称「西沢ツール」（表計算ソフト上でダイヤ等を入力するとGTFS-JP一式を生成するツール）が事実上の普及ツールとして使われてきた。

一方で、表計算ベースのツールには次の課題がある。

- 複数人での同時編集・版管理が難しい
- 入力ミスの検知（バリデーション）がツール任せで、公開後に発覚することがある
- 生成したzipの「公開URLでの安定配信」は別途自前で用意する必要がある
- GTFS-RT（リアルタイム）との連携が前提になっていない

本サービスは、西沢ツールの「表形式でダイヤを入力する」という使い勝手の良さを継承しつつ、Webサービスとして上記課題を解決し、**作成 → 検証 → 公開（配信）→ 更新**までを一気通貫で支援することを目的とする。

## 1.2 目的・ゴール

- 交通事業者・自治体・支援者が、専門知識を最小限にGTFS-JP準拠データを作成・公開できる。
- 既存の西沢ツール資産（スプレッドシート/CSV）からの移行を容易にする。
- 公開フィードを安定URLで配信し、Google Maps等のデータ利用者へ供給できる。
- 将来的にGTFS-RTを同一プラットフォーム上で配信できる素地を持つ。

## 1.3 コンセプト

> **「ダイヤを入力すれば、検証済みの公開GTFSが出てくる」**

- 一次データは「停留所マスタ」「系統パターン（停留所の並び）」「ダイヤ（便と時刻）」「運行カレンダー」。
- これらから GTFS-JP の各ファイルを機械的に展開する。
- 編集は常時バリデーションされ、公開はワンクリック（版を確定して配信）。

## 1.4 プロジェクトの立ち位置（OSS＋コミュニティサポート）

本サービスは、先行する「西沢ツール」への敬意の上に成り立つ。

- **西沢ツールの実績への称賛**: 西沢明氏が開発し**無償公開**した通称「西沢ツール」は、専門家でなくとも表計算ソフト上でGTFS-JPを生成できる事実上の標準ツールとして、日本の公共交通オープンデータ普及に決定的な役割を果たしてきた。本サービスはこの功績と思想を直接の出発点とし、その出典を明記して敬意を払う。
- **商用SaaSの台頭という現状認識**: 近年は、GTFS整備をクラウド化する**商用SaaSサービスを民間企業が提供開始**するなど、整備手段の選択肢が広がりつつある。これは普及にとって歓迎すべき流れである。また、仕様面では国交省の**GTFS-JPアップデートプロジェクトによりv4へ改訂**（2025年度）され、流通面では**GTFSデータリポジトリ**（日本バス情報協会協力）が国内フィードの約半数を集約するなど、エコシステム全体が次の段階に入っている。本サービスはこの新しいエコシステム（v4準拠・リポジトリ連携）を前提に設計する。
- **本サービスの姿勢＝OSS＋コミュニティサポート**: 私たちは、西沢ツールが築いた「**誰もが無償でGTFSを作り、公開できる**」という公共的価値を継承する。そのため、本サービスの**ソースコードをOSSとして公開**する。SaaSとしての提供も行うが、自治体・事業者が自前環境（オンプレ／自己ホスティング）で運用できる自由を保証し、特定ベンダへのロックインを生まない。継続的な改善は**コミュニティによるサポートと貢献**を中核に据える。商用SaaSと競合するのではなく、共通基盤としてのオープンな選択肢を社会に残すことを目的とする。

> 要約: **西沢ツールの志を、OSSとコミュニティで次世代に引き継ぐ。** SaaSは利便性のための一手段であり、独占の手段にはしない。

### 1.4.1 エコシステム内のポジショニング（どこで価値を出すか）

国内GTFSエコシステムを「作成・検証・流通」の3層で整理すると、本サービスが価値を出すべき場所が明確になる。

| 層 | 既存の担い手 | 本サービスの方針 |
|----|--------------|------------------|
| **流通・配信** | GTFSデータリポジトリ（無償。国内フィードの約半数を集約、Mobility Database連携） | **競合しない。連携する**（F-7-7）。自前配信URLは補助に位置づける |
| **検証** | MobilityData標準バリデータ（OSS）、v4のGoogle受入基準 | 標準を内部実行しつつ、**編集中のリアルタイム検証**という空白を埋める |
| **作成・編集** | 西沢ツール（無償・表計算）、無償デスクトップツール、商用SaaS | **主戦場**。Webベースの協働編集＋常時検証＋v4ネイティブのOSSはここに不在 |

本サービスの存在意義は次の3点に立脚する。

1. **v4移行のタイミング**: 既存の作成ツール群は旧版（v3系）世代に最適化されている。v4は独自拡張を整理し国際標準へ整合したため、**レガシー互換の負債なしにv4ネイティブで実装できる今が、新規参入の好機**である。
2. **属人性からコミュニティへの継承**: 作成ツール層は長く個人の貢献（西沢ツール）に支えられてきた。この資産を**個人依存からコミュニティ維持へ引き継ぐ**ことは、エコシステム自体の持続可能性の課題であり、OSS＋コミュニティという形態はその直接の解である。
3. **商用が埋めない領域**: 予算の乏しい小規模自治体・支援者・地域ベンダーが共通に使える「上に乗れる基盤」は、商用の合理性だけでは生まれにくい。

### 1.4.2 やらないこと・競合しないこと

- GTFSデータリポジトリの再発明（フィード集約・カタログ機能）は行わない。
- 既存コミュニティ（日本バス情報協会・西沢ツール利用者コミュニティ等）と**分断する形での展開は行わない**。立ち上げ初期から既存コミュニティへの連携・協調を最優先で打診し、可能であれば「作成ツール層の共同後継」の位置づけを目指す（[08](./08-tech-roadmap.md) 8.8）。
- 商用SaaSの否定はしない。本サービスのOSSを基盤に商用サポートが成立することはむしろ歓迎する（Apache-2.0の選択はこの含意）。

## 1.5 スコープ

### 対象（In Scope）

- GTFS-JP（静的）データの作成・取込・編集・検証・出力・配信
- 西沢ツール様式 / CSV / GTFS-JP zip のインポート
- フィードの版管理と安定URL配信
- GTFS-RT（TripUpdate / VehiclePosition / Alert）の配信基盤（フェーズ2以降で本格対応）
- マルチテナント（事業者単位のプロジェクト管理）と権限管理

### 対象外（Out of Scope）※初期リリース

- ダイヤそのものを最適化・自動生成する機能（ダイヤ作成支援AI等）
- 運賃計算エンジン・経路検索エンジンの提供（あくまでデータ生成・配信に徹する）
- 車載器・ロケーションシステムのハードウェア提供（GTFS-RTは外部入力の取込に徹する）

## 1.6 用語定義

| 用語 | 説明 |
|------|------|
| GTFS | General Transit Feed Specification。公共交通データの国際標準フォーマット。 |
| GTFS-JP | 国交省の日本標準仕様。旧称「標準的なバス情報フォーマット」、2025年度改訂で「公共交通運行情報標準データ仕様（GTFS-JP）v4」へ。v4は国際標準との整合を強化し、Google Maps受入基準に基づく必須区分を持つ。旧版は`*_jp.txt`等の独自拡張を含む。 |
| GTFSデータリポジトリ | 日本バス情報協会協力のもと運営される国内GTFSフィードの集約・公開基盤（gtfs-data.jp）。国内オープンデータの約半数が登録され、Mobility Databaseへも反映される。 |
| GTFS-RT | GTFS Realtime。遅延・車両位置・運行情報をProtocol Buffersで配信する動的仕様。 |
| フィード（Feed） | 配信単位となるGTFSデータ一式（`gtfs.zip`）。通常は事業者または事業者群に対応。 |
| 事業者（Agency） | 運行主体。`agency.txt` の1行に対応。 |
| 停留所（Stop） | バス停。標柱（platform）と停留所（station）の親子関係を持つことがある。 |
| 経路（Route） | 路線・系統。`routes.txt` の1行。 |
| 系統パターン（Pattern） | 経路の中で「停留所がどの順で並ぶか」の型。本サービスの一次データの中核（後述）。 |
| 便（Trip） | 1回の運行。`trips.txt` の1行。 |
| 通過時刻（Stop Time） | 便が各停留所を通過する時刻。`stop_times.txt`。 |
| 運行区分（Service / Calendar） | 運行する曜日・期間・例外日。`calendar.txt` / `calendar_dates.txt`。 |
| 描画（Shape） | 経路の地図上の線形。`shapes.txt`。 |
| プロジェクト | 本サービス上の編集単位。1フィードに対応するワークスペース。 |
| 版（Revision） | 公開のために確定したフィードのスナップショット。版番号で管理。 |

## 1.7 想定利用シナリオ

1. **新規作成**: コミュニティバスを運行する自治体担当者が、停留所・系統・ダイヤをWeb UIで入力し、検証して公開URLを取得。Google Mapsへ申請。
2. **西沢ツールからの移行**: 既にExcelの西沢ツールで運用している事業者が、ファイルをインポートして以後はWeb上で更新。
3. **ダイヤ改正**: 既存フィードを複製して改正後のダイヤを編集、施行日を予約して新版を公開。
4. **リアルタイム化**: 静的GTFSを公開済みの事業者が、車両位置の外部入力を接続してGTFS-RTを追加配信。
